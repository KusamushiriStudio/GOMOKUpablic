# 現行ホーム画面の分析（§0-16 の 1・2）

完成イメージ（ユーザー提示の 1 枚）と、いまの実装を突き合わせた結果。
行番号は分析時点の `index.html`。

実装の在り処：`__def("views/home.js")` と `__def("views/home-stage.js")`、
CSS は 1170–1500 と 1790–1805。

いまの縦の構成は
**和紙色の帯 → 舞台カード(44svh) → 木札2枚 → 木札3枚 → 説明カード5枚**で、
390×844 でページ全体が約 1,830px（約 2.2 画面）。

## 効き目の大きい差

### 1. 立ち絵が完成イメージの半分以下

`.stage-char`（1297）は `width: clamp(122px, 42%, 188px)`。
`.app-main`（113–119）の `padding: 12px 10px` で舞台幅は 370px、その 42% で **155px**。
`characterHero()` は `viewBox="0 0 240 330"` だが中身は `translate(0 22) scale(2)` で
y=46〜314 しか描かないため、**実描画高は約 173px＝画面高の 20.5%**。

完成イメージは画面高の約 45%（≒380px、幅で約 276px）。**面積で 31%**しかない。

### 2. 舞台がカードの中に閉じている

`.home-stage`（1215–1223）は `height: var(--stage-h)` ＝ 844px 端末で 371px、
`border-radius: 16px` `overflow: hidden` の角丸カード。
さらに `.app-main` の `padding: 12px 10px` で左右に 10px 残り、地が画面端に届かない。

完成イメージは**夜の神社が画面全体の地**で、その上に UI が浮く構成。

### 3. 最上段の帯が黒漆でなく和紙色

既定テーマは `sumi`（2833）で body は `#0e1211`。
なのに `.home-topbar`（1178–1185）は `linear-gradient(180deg, var(--washi), var(--cream-2))` のまま。
`:root[data-theme="sumi"] .home-` / `.stage-` / `.mokufuda` というセレクタは**1 件も無い**。
sumi では `--cream-2` が `rgba(244,238,226,.20)` に変わるので、
帯は上が不透明クリーム・下が半透明という中途半端な見えかたになる。

## トークン側で見つかったこと

### `@media (prefers-color-scheme: dark)` が墨の部分写しで、第 3 の見た目が生まれている

782–805 の `:root:not([data-theme="washi"])` は 730–780（sumi）の一部しか写していない。
`--fill-primary/-sub/-gold/-danger/-urushi`・`--washi-grain`・`--glow-kin`・
`--shiro`・`--line-shu`・`--shu-ink`・`--ai-ink`・`--on-urushi` が抜けている。

結果、`data-theme` 未設定＋OS ダークだと、面は暗いのに
`--fill-sub` は和紙値の `linear-gradient(180deg, #fffefa, #f4efe1)`（ほぼ白）のまま残る。

**これは実装側の不具合。** Figma は 2 モードしか持たないので、この第 3 の状態は再現しない。

### `--kinpaku` の金箔グラデは潰れている

718–721 で 7 停点のグラデを定義しているが、1164 の別の `:root` が
`--kinpaku: #e8c561;` と**同じ詳細度で後ろから単色に上書き**している。
`.num-kin` の金箔文字も木札の家紋も、実際は単色。

### 定義だけあって一度も使われていないトークンが 39 個

`--mark-*` 8 個すべて、`--fs-1/3/6/7/8`、`--lh-base/loose`、
`--sp-1/5/6/7/8`、`--r-4/5/pill`、`--gutter`、`--seat-*-deep`、`--ai*`、`--warn*` ほか。

`00_DesignSystem` の "NOT WIRED UP" に並べてある。**Figma で使う前に実装側を繋ぐこと。**

### 見出し・本文は `var(--fs-*)` を通っていない

`.card > h2` は直値 15px（`--fs-4`=14 でも `--fs-5`=16 でもない）、
`.mokufuda .fuda-main` は 23px（`--fs-7`=22 に近いが不一致）、`.muted` は 12px。
`var(--fs-*)` が実際に書かれているのは 8 箇所だけ。

**Figma の文字スタイルは実値で作った。** トークンの理想形を写すと、実画面と必ず食い違うため。

## Blender 素材（§0-11）

完成イメージのホームに必要なものは、ほとんど既にある。

**作らない**：立ち絵（装備 864 通りの合成）・丸肖像・碁石（席色の正典は
`SEAT_COLORS`）・滝／社殿／桜／満月（`data-fx` 連動）・バナー（文面が入れ替わる）・
筆文字ロゴ・UI アイコン（テーマ 2 色に追随できなくなる）。

**既にあるのに使っていない**：
- `prop_torii.webp` … 物語のボス門 1 箇所だけ。ホームの遠景は SVG の矩形 6 本
- `board_default.webp` … `assets.js` の `ASSETS` 表に無く、**どこからも参照されていない**

**新規に要るのは 3 つだけ**：
1. `prop_coin`（金貨・512 段のみ・約 6KB・800 三角形）— いまは `◎` の 1 文字
2. `prop_plate_diamond`（菱形の額・512+1024・約 22KB・900 三角形）— 1 枚で 6 箇所に使える
3. `board_default_front`（既存モデルの低角度撮り直し・三角形 0・約 37KB）

青い宝玉は**作らない**。通貨がデータモデルに無いのに素材だけ先に作るのは §0-11 に反する。

`.glb` は作らない。`index.html` に three.js / model-viewer / WebGL が 1 行も無く、
`assets/models/*.glb`（10 本 688KB）は**ゲームから到達できない**。

**転送量の上限案**（実測 `index.html` = 729,400B / gzip 195,986B）：
ホーム画像の合計 **102,400B**、画面内で即座に要求してよい分 65,536B、1 ファイル 32,768B。
計画値は 75,780B。

## 併せて直すこと

- `assets.js`（3902・3937）が全アセットに 2048 段を一律で `srcset` に入れている。
  碁盤を足すと高 DPR 端末が装飾に 74KB 取りに行く。エントリごとに上限段を持たせる。
- 新しい webp をコミットしたら `ASSET_COMMIT`（3896）の更新が必須。
  忘れると全部 404 になり、`img.onerror` が黙って消すので**気づけない**。
- `b2ac51a` 以降、`board_default` のレンダーを再実行していない。
