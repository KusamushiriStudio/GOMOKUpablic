# TRIAD UI/UX 段階開発・外部ツール評価方針

## 目的

TRIADの既存機能を維持しながら、Figma、Unity、Blender、Riveを役割別に使い、UI/UXを小さな単位で改善する。同時に、無料機能を実際のゲームで検証してから外部ツールへの課金価値を判断する。

## 開発原則

各UIは次の順序で進める。

1. 小さな単位をFigma無料プランで制作する。
2. Unity uGUIへ実装する。
3. 実ゲームへ反映する。
4. スクリーンショットまたは実機で確認する。
5. デザインとの差、導入効果、無料版の制限を確認する。
6. Phase報告を行い、人間の確認後に次の小単位へ進む。

画面全体の一括改修、完成画像1枚の貼り付け、Figmaだけで完結する制作、確認前の次Phase着手は禁止する。

## デザイン基準

- 和風幻想、夜桜、神社、月
- 黒・濃紺・金を中心とした配色
- 高品質なキャラクターイラストと高級感のある金装飾
- 商用スマートフォンゲーム相当の情報密度
- 現在の豪華版ホーム画面を方向性の基準とする
- 背景、キャラクター、ボタン、カード、文字、アイコン、演出、ナビゲーションを独立操作可能な要素として実装する

## ツールの役割

### Figma

UIデザインの正本。レイアウト、画面構成、Design System、ボタン、パネル、カード、文字、色、余白、金枠、コンポーネント、画面遷移を管理する。無料プランから開始し、Unityが独自にデザインを変更しない。

### Unity

最終ゲーム本体。uGUI、入力、遷移、アニメーション、Particle、Shader、Audio、キャラクター表示、Figma再現、Rive Runtime、Blenderモデル表示、実機確認、ビルド、テストを担当する。

### Blender

碁盤、碁石、3Dオブジェクト、一部背景オブジェクト、3D演出素材を担当する。既存の Blender → FBX → Unity Pipelineを使用し、UIは作らない。

### Rive

マイクロアニメーション専用。ボタン、通知、ガチャ、新章、選択状態、ローディング等をState Machineで補助する。最初は1要素だけを無料範囲でUnityへ導入して評価し、画面全体には使用しない。

### Codex

進行管理、役割整理、Unity/C#実装、Prefab、Scene、自動化、テスト、Git、成果確認、課金判断資料を担当する。確定デザインを簡略化せず、ゲームとして忠実に実装する。

## 無料版先行と課金ゲート

外部ツールは次の順序を守る。

無料機能を使用 → 小規模テスト → ゲームへ実装 → 効果確認 → 実際の不足確認 → 有料版と代替策を比較 → 人間が判断

推測だけで無料検証を省略しない。有料プラン、プラグイン、Asset、Blender Add-on等を無断で契約・購入しない。

### Figma課金判断報告

無料版の具体的な制限へ実際に到達した場合だけ、次を報告する。

1. 無料版で完成したもの
2. ゲームへ反映済みのもの
3. 無料版でできなかったもの
4. 現在遭遇している具体的な制限
5. Professionalで解決するもの
6. Professionalでも解決しないもの
7. 課金によるTRIADへの具体的効果
8. 課金しない場合の代替方法
9. 現在のスクリーンショット
10. 判断に必要な次の情報

### Rive課金判断報告

- 無料でできたこと／できないこと
- 必要な有料機能とTRIADへの効果
- UnityまたはFigmaでの代替可否
- 課金するメリットと、課金しないデメリット

## ホーム画面のPhase

1. Header：TRIADロゴ、通貨、メール、通知
2. Player Status：アイコン、名前、Lv、EXP、段位、称号
3. Hero Area：背景、ヒバナ、キャラクター情報、左ショートカット
4. Story Banner：新章、告知、カルーセル
5. Main CTA：対戦、物語
6. Sub Menu：世界、ガチャ、着せ替え、キャラ強化
7. Community：交流、プレイヤーコード
8. Bottom Navigation：ホーム、対戦、キャラ、ガチャ、着せ替え、メニュー
9. Rive Animation：通知、選択、新章、ガチャ等を1要素ずつ

現在の作業対象はPhase 1のみ。Phase 1の承認前にPhase 2へ進まない。

## Phase完了条件

- Unityへ反映済み
- Compile Error 0
- 対象UIが実際に表示される
- 既存機能を破壊していない
- iPhone縦画面で確認可能
- スクリーンショット取得済み
- Figmaデザインとの差を確認済み
- 次Phaseへ進める状態

## 既存機能の保護

3人対戦、オンライン対戦、ストーリー、ガチャ、着せ替え、フレンド、ランキング、通知、保存、アカウント、バックエンド連携をUI改修で破壊しない。UIとゲームロジックを分離し、既存ロジックを不要に変更しない。

## Git運用

Phase単位の小さなブランチ・コミットを基本とする。例：`ui/home-header`、`ui/home-player-status`、`ui/home-hero`、`ui/home-bottom-navigation`、`ui/home-rive-notification`。大規模な一括コミットを避け、1工程単位で戻せる状態を維持する。
